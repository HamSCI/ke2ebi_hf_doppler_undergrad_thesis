# Core GrapeDRF engine and eclipse Doppler work (W2NAF)

This repository began as **`grapeDRF_doppler_model`** by Dr. Nathaniel Frissell (W2NAF) — "code for
plotting GRAPE DigitalRF data with Shibaji Chakraborty's HF Doppler Model outputs on top," with an
early focus on HF Doppler signatures of solar eclipses. That original project supplied the core data
engine and solar/eclipse computation library that everything else in this repository — including the
thesis figures — is built on. See the [development history in the README](../README.md#development-history)
for the full lineage.

## `grapeDRF.py` — the shared spectrogram engine

`grapeDRF.py` defines the `GrapeDRF` class, the engine used throughout the repository (and by all of
the thesis multi-day spectrogram/stackplot scripts). Given a start date, end date, and a station data
directory under `data/psws_grapeDRF/`, it:

- loads the GRAPE / RX888 DigitalRF I/Q recording for the requested window (caching the assembled
  "big array" as a `.ba.pkl` in `output/grapeDRF/` so repeat runs are fast);
- computes per-frequency Doppler spectrograms; and
- overlays the **solar elevation angle** (and, optionally, eclipse obscuration) using the
  `eclipse_calc` library described below — this is the white dash-dot curve seen on the thesis
  spectrograms.

It is imported as a module (`import grapeDRF`) rather than run directly; the thesis figure scripts
construct `grapeDRF.GrapeDRF(sDate, eDate, data_source)` and call its plotting methods. See the
[top-level README](../README.md) for how the thesis scripts use it.

`load_metadata.py` (Gwyn Griffiths, G3ZIL, using `data_dict` code by W2NAF) is the companion helper
that reads a station's DigitalRF metadata (center frequencies, sample rate, location, grid square)
for the analysis scripts.

## `eclipse_calc/` — solar and eclipse computation library

The `eclipse_calc/` package provides the solar-geometry and eclipse routines that the engine draws
on. It depends only on standard scientific Python packages (NumPy, pandas, geographiclib) — **not**
on PyLap — so it loads fine in environments without the ray-tracing stack.

| Module | Purpose |
| --- | --- |
| `solarContext.py` | Solar azimuth/elevation (`sunAzEl`), solar zenith angle, and the `EclipseData` class for loading and overlaying eclipse obscuration grids. |
| `calcSun.py` | Solar position (`calculate_solarAzEl`). |
| `eclipse_calc.py` | Eclipse obscuration calculation (`calculate_obscuration`). |
| `locator.py` | Maidenhead grid-square ↔ latitude/longitude conversions. |
| `maps.py` | Cartopy map helpers. |
| `geopack.py` | Geomagnetic coordinate transforms. |
| `rayTracePaths.py` | Great-circle / ray-path helpers (geographiclib). |
| `gen_lib.py` | General-purpose helpers. |

## Eclipse Doppler plotting

The original project's headline product was a W2NAF eclipse Doppler plot (the 8 April 2024 total
solar eclipse), generated by a `plot_w2naf_grapeDRF_2024eclipse.py` script that drove `GrapeDRF` and
overlaid solar/eclipse context.

That standalone eclipse script was **removed during the thesis-archival cleanup**: by then it had
drifted (it pointed at a non-existent data directory and plotted the May 2024 Gannon storm rather
than the eclipse) and was redundant with the thesis stackplot scripts, which use the same `GrapeDRF`
engine. The engine and `eclipse_calc` library it relied on remain, so an eclipse Doppler figure can
still be produced by constructing `GrapeDRF` for the eclipse-day data
(`data/psws_grapeDRF/ch0_W2NAF_2024-04-08`) with `overlayEclipse=True`; see the thesis scripts (e.g.
`Gannon_storm_stackplot.py`) for the calling pattern.
