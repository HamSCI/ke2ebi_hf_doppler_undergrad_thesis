# Synthetic spectrograms (G3ZIL)

This set of scripts, developed by Gwyn Griffiths (G3ZIL), derives and plots a synthetic Doppler
spectrogram by running a series of ray-trace simulations using PyLap while also identifying the
propagation modes. It is not used to produce the thesis figures; it is broader tooling that ships
in this repository. For the thesis workflow, see the [top-level README](../README.md).

> **Requirement:** these scripts require the ray-tracing package PyLap, installed from
> [GitHub](https://github.com/HamSCI/PyLap). As of September 2025 PyLap only assuredly works with
> PHaRLAP 4.5.0, and its `setup.sh` may have issues in a protected environment. Optionally,
> `synthspec.py` can write its data to a PostgreSQL database on localhost; contact the author for
> details if you are interested in this option.

**Limitation:** the `pathfinder.sh` start time in its `config.ini` file and the command-line
duration in minutes must remain within one day UTC (that is, they must not span 00:00 UTC).

## Part 1: Finding all rays from the transmitter that land at a receiver via great-circle paths (2D ray tracing)

`pathfinder.py` runs PyLap ray tracing at a single specified time over a sweep of elevations
incrementing by 0.005° to find all ray elevations landing at a receiver from a given transmitter
location. It generates a CSV file in the `output/csv/<receivercallsign>` subdirectory. The PyLap
configuration is specified in a config file with the naming convention `<receivercallsign>_config.ini`
in the `config` subdirectory (example below). The config file name and the specified time in
`YYmmddHHMM` format are the two command-line parameters to `pathfinder.py`:
```
python3 pathfinder.py ./config/N8GA_config.ini 202407260000
```

`pathfinder.sh` runs a sequence of `pathfinder.py` calls over an interval specified in minutes.
Currently it runs ray traces at five-minute steps, so the following produces a CSV file with data
every five minutes for 30 minutes:
```
./pathfinder.sh N8GA_config.ini 30
```

`config.ini` — this example is for WWV Fort Collins, CO to N8GA Ohio:

```ini
[settings]
ut = [2024,7,26,0,0]
r12 = 120
freq = 10
tx_grid = DN70LQ
rx_grid = EN80EE
nhops = 2
elev_start = 2
elev_stop = 45
[metadata]
tx = WWV
rx = N8GA
```

An example CSV file output for one five-minute interval is:

```
"Date, Hops, Init_elev, one_hop_virt_ht, one_hop_apogee, 2nd hop apogee, gnd_range, phase_path, geo_path, pylap_doppler"
2024-07-26 00:00:00,1,2.55,102.292,96.046,nan,1813.148,1834.42,1835.975,-0.173
2024-07-26 00:00:00,1,13.68,238.466,138.634,nan,1813.192,1826.658,1865.551,-4.324
2024-07-26 00:00:00,2,33.07,nan,218.983,221.31,1813.605,1942.765,2077.204,-7.736
```

_Note that there is probably an issue (September 2025) with PyLap's own Doppler computation._

## Part 2: Assigning a propagation mode to each ray that landed at the receiver

After reading the CSV of ray parameters generated by `pathfinder.py`, `modefinder.py` tests each ray
against a set of heuristics (rules of thumb) to assign each ray a great-circle propagation mode.
These are outputs of 2D ray tracing. The code currently tests each ray against the modes:

```
1E   1E high ray
2E   2E high ray
1F   1F high ray
2F   2F high ray
```

where the initial numeral is the number of hops and high rays are rays with steeper elevation angles
that penetrate higher into the ionosphere and so can land at the same distance as a lower-elevation
ray. Some of these high rays will be ducted (Pedersen) rays; a test for those will be added to the
heuristics. The current heuristics, in `heuristics.ini` in the `config` subdirectory, are:

```ini
[propagation]
min_apogee_E=85
max_apogee_E=150
min_apogee_F=151
min_hdashF-hF=45
max_hdashF-hF=85
elev_diff_lo_hi=0.5
sep_EloEhi=5
; September 2025 heights are in km, elevations in degrees
```

The script is called with two command-line arguments, the subdirectory callsign and start datetime
as in `pathfinder.py`:
```
python3 modefinder.py N8GA 202407260000
```
The output is a CSV file in `./output/csv/<callsign>` with mode designators and a color for each
mode, and a plot in `./output/plots/<callsign>`. The plot is a scatterplot of initial ray elevation
angles arriving at the receiver against time, color-coded by propagation mode:

## Part 3: Synthesizing a spectrum: Doppler shift for each propagation mode

`synthspec.py` reads the CSV generated by `modefinder.py`, calculates Doppler shift from the
difference in phase path between successive time intervals, and outputs a CSV file (optionally
uploading to a database). It is called with two mandatory command-line arguments, the subdirectory
callsign and start datetime as in `modefinder.py`. An optional third argument `DB` triggers data
upload to a local PostgreSQL database:
```
python3 synthspec.py N8GA 202407260000
```
The raw Doppler estimate (rate of change of phase path) is adjusted to account for the actual ground
landing distance, because jitter (rms ~400 m in the ray landing distance with 0.005° elevation
increments) adds noise to the Doppler estimate. After this correction the assigned-to-mode Doppler
shifts are (with a few outliers) smooth:

<img width="800" height="400" alt="WWV-N8GA_GG_doppler" src="https://github.com/user-attachments/assets/9979da4d-5730-480c-8eeb-cbaf968b8087" />

`synthspec.py` also calculates and plots the propagation delay separated by mode.

## Part 4: Overlaying as-received and synthetic spectrograms

`grape_fft_spectrogram.py` (see [GRAPE DRF analysis](grape_drf_analysis.md)) can be used with an
optional fifth command-line argument `DB` to overlay as-received and synthetic spectrograms. The
synthetic spectrogram data must already be in the local PostgreSQL database — that is, `synthspec.py`
must have been run with the `DB` option and a local database configured:
```
python3 grape_fft_spectrogram.py ch0_W2NAF_2024-04-08 7 0 24 DB
```
This produces the plot below. There are several differences between the two, but each likely tells
us something about actual propagation compared with the climate of the International Reference
Ionosphere.
